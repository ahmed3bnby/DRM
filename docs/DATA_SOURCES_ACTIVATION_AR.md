# خطة تفعيل مصادر البيانات الحقيقية (Real Screening Data)

> الهدف: الوصول بتغطية الفحص لمستوى قريب من تقارير المنصات التجارية (مثل Idenfo)
> عبر البنية الموجودة عندنا، مع الوضوح والأمانة في التمييز بين المتاح مجانًا والمرخّص.

## الوضع الحالي (شغّال فعلًا)

Pipeline استيراد حقيقي عبر **OpenSanctions**:

```
scripts/watchlist.json  →  scripts/sync.mjs  →  scripts/connectors/opensanctions.py (تحميل CSV)
                        →  scripts/import-sources.ts  →  PostgreSQL (source_versions/records/names/imports)
```

- ~**٢٣٨ ألف سجل حقيقي** قبل التوسعة، من قوائم عقوبات/حظر حقيقية.
- كتالوج OpenSanctions فيه **٤٧٩ داتاست**، كلها تُحمّل بنفس الموصّل.
- الموصّل يحمّل `targets.simple.csv` لكل داتاست ويحوّله لشكل سجلاتنا (`parsed.json`).
- `sync.mjs --changed-only` يستورد الجديد/المتغيّر فقط، ويحفظ آخر نسخة ناجحة عند فشل أي تحميل.

## المراحل

### مرحلة ١ — توسيع العقوبات + PEP + Special Interest ✅ (جارية)
أُضيفت لـ `watchlist.json` (من ٢٥ → ٤١ داتاست):

- **عقوبات ناقصة:** `ir_sanctions` (إيران)، `sa_pcct_terrorism_list` (قائمة الإرهاب السعودية)، `pk_proscribed_persons` (NACTA باكستان — نفس مصدر تقرير Idenfo).
- **Special Interest / جريمة / إنفاذ:** `interpol_red_notices`، `eu_europol_wanted`، `gb_nca_most_wanted`، `us_fbi_most_wanted`، `crime`، `enforcement`.
- **شركات مملوكة للدولة (SOE):** `eiti_soe`.
- **PEP واسع:** `pk_na_members`، `pk_senate_members`، `eu_meps`، `us_cia_world_leaders`، `wd_peps`، `everypolitician`.

التشغيل: `node scripts/sync.mjs --changed-only`.

### مرحلة ٢ — تصنيف PEP (Tier 1/2/3) + الأقارب/المرتبطين (RCA) ✅
- `pepProfile()` في `src/lib/risk.ts` يقرأ `topics` (`role.pep` / `role.rca`) + heuristic على نص المنصب والمصدر.
- **Tier 1**: قادة/وزراء/برلمان وطني/سفراء/MEPs (`us_cia_world_leaders`, `*_na_members`, `*_senate`, `eu_meps`). **Tier 2**: إقليمي/محلي. **Tier 3**: باقي الـ PEP.
- **RCA**: علم مستقل (`role.rca`) — يظهر عند إضافة قوائم RCA لاحقًا.
- يظهر في نتائج البحث (شارة «PEP · المستوى ١») ويُحفَظ مع الفحص للملف.

### مرحلة ٣ — الإعلام السلبي (Adverse Media) ✅
- `src/lib/adverse-media.ts` — تكامل **GDELT DOC 2.0** (مجاني، بدون مفتاح).
- الاستعلام يضيّق الأخبار العامة لمؤشرات سلبية (احتيال/غسل أموال/فساد/عقوبات/إرهاب/جريمة) ويصنّفها بالفئة.
- يظهر قسم «الإعلام السلبي · GDELT» في صفحة البحث بروابط خارجية وتنبيه: «إشارة للمراجعة فقط، ليست إثباتًا».
- مرن: يتعامل مع حد المعدّل (١ نداء/٥ ثوان) كفشل مؤقت دون ادعاء «لا نتائج».

### مرحلة ٤ — مصفوفة المخاطر + مطابقة تقرير Idenfo ✅
- حقلان جديدان: **الجنسية** و**قناة التعامل** (migration `010` + المخطط + الفورم).
- `src/lib/risk-rating.ts` — نموذج مخاطر: مصفوفة عوامل (إقامة/جنسية/نشاط/قناة) بجدول درجات + تجاوزات من الفحص المحفوظ (عقوبات/PEP/جريمة/رقابي).
- الإجمالي **اقتراح نموذجي**، القرار النهائي للمحلل (مبدأ #3) — لا يُحسب تلقائيًا من الاسم.
- صفحة الملف: لوحة «تقييم المخاطر (نموذج)» + إحصاء حسم المطابقات (مؤكّدة/مستبعدة/غير محسومة) = resolved/unresolved.
- سجل التدقيق موجود بالفعل (الجدول الزمني للملف).
- تحقق: عميل سوداني مقيم بالإمارات + إصابة عقوبات → **مرتفع** (مطابق لمنطق Idenfo).

### مرحلة ٥ — التحديث التلقائي ✅
- `scripts/sync-cron.sh` محصّن بقفل وحيد النسخة (يمنع التداخل) + تنظيف قفل معلّق قديم.
- **جدولة launchd يومية (٣:٣٠ ص):** `npm run sources:schedule` (تثبيت لمرة واحدة، بدون sudo) و`npm run sources:unschedule` للإزالة.
- تستورد المتغيّر فقط (`--changed-only`)، وتسجّل في `.local/sync-cron.log`.
- صفحة «مصادر البيانات» تعرض آخر تحديث لكل قائمة (مؤشّر الحداثة).

**للتفعيل:** شغّل `npm run sources:schedule` مرة واحدة على جهاز الخادم.

## ⚠️ ملاحظة الترخيص (مهمة قبل الاستخدام التجاري)
بيانات OpenSanctions عامة ومفتوحة الترخيص غالبًا، **لكن** الاستخدام التجاري الفعلي (قرار فحص لعميل حقيقي)
يستلزم مراجعة ترخيص كل داتاست على حدة. التغطية العالمية الشاملة لـ PEP/RCA والإعلام السلبي الاحترافي
قد تتطلب **مجموعات بيانات تجارية مرخّصة**. لذلك تُعرَض التغطية في الواجهة مقسّمة:
«متاح الآن (مصادر عامة)» و«يتطلب مزوّد مرخّص».

## المراحل ١–٥ كلها مكتملة ✅

### تحسينات إضافية
- **الموصّل — fallback لـ simple.csv:** عند غياب/فراغ `targets.nested.json` يجرّب `targets.simple.csv` تلقائيًا (robustness لداتاسِتس مستقبلية). ملاحظة: `crime` (٣٧٧م، مكرّر)، `eiti_soe` و`wd_peps` تصديراتها فارغة من الأهداف أو غير متاحة، فاستُبعدت.
- **الإعلام السلبي مربوط بالفحص:** عند فحص العميل يُلتقط مسح GDELT ويُخزَّن مع الفحص (migration `011`)، ويظهر قسم «الإعلام السلبي» في الملف **وفي صفحة التقرير/التصدير**، ويدخل كعامل تجاوز في نموذج المخاطر — مطابقة لـ «Adverse Media Hit» في تقرير Idenfo.
- **صفحة التقرير موسّعة:** الجنسية + قناة التعامل + تقييم النموذج + حسم المطابقات (مؤكّدة/مستبعدة/غير محسومة) + قسم الإعلام السلبي.
- **مصادر PEP إضافية + تفعيل RCA:** أُضيفت ٦ قوائم (نيجيريا join-dots، كولومبيا join-dots، Chipper، فرنسا، الدنمارك، التشيك) → الإجمالي **٧٣٧ ألف سجل / ٤٦ قائمة**، ومنها **٢٠٤٤ سجل RCA حقيقي** (أقارب ومرتبطون) — فعّلت علم «قريب/مرتبط (RCA)» في نتائج البحث والفحص.
