## تحديثات المراحل المنفذة

### P04 — منظومة المصادر والعقوبات الأساسية

- المرحلة وتاريخ التحديث: P04 · 21 سبتمبر 2026.
- الحالة والمسؤول: قيد التنفيذ · التطوير.
- معرفات المهام المنجزة: P04.1 (واجهة موحدة: connectors لـ OpenSanctions وEOCN والقوائم العامة)، P04.2 (نسخة أصلية + SHA-256 + تاريخ الجلب + إصدار المحوّل + سجل مزامنات `source_imports`)، P04.3 (نشر ذرّي + حارس هبوط العدد 75%)، P04.4 (UN/UK/OFAC + EU + UAE-EOCN)، P04.5 (الاحتفاظ بالإصدارات وعدم الاستنتاج من استيراد ناقص)، P04.7 (صفحة المصادر: السجل وآخر تحديث والجديد/المحذوف والمزامنة اليدوية). جزئيًا P04.6 (قفل advisory ✅؛ الجدولة والإعادة المنضبطة موثقة كأمر واحد ولم تُؤتمت بعد).
- السلوك الذي يمكن تجربته الآن: `npm run sources:catalog` يبني سجل 479 قائمة ويكشف المتغيّر؛ `npm run sources:sync` ينزّل ويستورد ويسجّل الجديد/المحذوف؛ `npm run sources:uae` يوثّق ملف EOCN الرسمي؛ صفحة «مصادر البيانات» تعرض القوائم وحالة تحديثها.
- دليل الاختبار والنتيجة: typecheck نظيف؛ منطق السجل والـparse متحقّق على بيانات حقيقية (479 قائمة، عيّنة CSV 354 سجلًا)؛ اكتشاف رابط EOCN المتغيّر متحقّق حيًّا على الموقع؛ صفحة المصادر متحقّقة بصريًا على نسخة تطوير.
- المهاجرات أو إعدادات التشغيل: `db/003_source_changes.sql` (يُطبَّق تلقائيًا داخل import-sources)؛ `.env.local` بـ APP_ENV=local وDATABASE_ADMIN_URL؛ `scripts/watchlist.json` لقوائم المتابعة.
- ما تبقى والاعتماديات: تشغيل الاستيراد الفعلي لقوائم المتابعة (شرط إغلاق P04)؛ الجدولة التلقائية والإعادة المنضبطة؛ اختبارات عينات لكل صيغة؛ مراجعة ترخيص الاستخدام التجاري (R01/P00.4).
- أثر التغطية: توسّع من 4 مصادر إلى سجل 479 قائمة عامة (عقوبات/PEP/إنفاذ/حظر) عبر OpenSanctions + مصدر EOCN مباشر؛ لا تُعتبر تغطية إنتاج قبل الاستيراد الفعلي والترخيص.
- الخطوة التالية: تشغيل `sources:sync`، جدولة `sources:sync:changed`، وبدء التقييم المنفصل لتاريخ الميلاد والمعرفات في P05.

### P05 — محرك الفحص والمطابقة (بداية)

- المرحلة وتاريخ التحديث: P05 · 21 سبتمبر 2026.
- الحالة والمسؤول: بدأ جزء مستقل · التطوير.
- معرفات المهام المنجزة: جزء من P05.2 (توحيد الاسم)، P05.3 (استرجاع المرشحين بالاسم/الأسماء البديلة عبر pg_trgm)، P05.5 (تفسير جزئي: نسبة المطابقة + الفئة + شدّة المطابقة).
- السلوك الذي يمكن تجربته الآن: بحث `/search?q=` يرجّع مرشحين مصنّفين بفئة تلقائية (عقوبات/PEP/حظر/إنفاذ من `collections` في OpenSanctions) و**شدّة مطابقة** (مرتفع/متوسط/منخفض) ونسبة%، مع بطاقة تقييم إجمالية.
- دليل الاختبار والنتيجة: متحقّق حيًّا على UN + UK؛ بحث «Muhammad Khallouf» أعطى تطابقًا تامًّا بشدّة مرتفعة (عقوبات · UK · 100%) وأسماء متشابهة بشدّة منخفضة (50–55%).
- ملاحظة توافق مع الخطة (مبدأ #3): **شدّة المطابقة ليست تقييم مخاطر العميل**؛ سُمّيت في الواجهة «شدّة المطابقة» لا «مخاطر»، ويبقى `risk_level` للعميل = unassessed. تقييم المخاطر النهائي وقرار المحلل من اختصاص P06.
- ما تبقى والاعتماديات: تقييم منفصل لتاريخ الميلاد والمعرفات ونوع الكيان (P05.3/P05.4)؛ مجموعة قبول وتقييم مستقلة وقياس الاسترجاع/الإنذارات (P05.7)؛ سير قرار المحلل والحالات (P06).
- الخطوة التالية: إضافة إشارات تاريخ الميلاد والمعرفات للترتيب، وربط زر «افحص هذا العميل» من ملف العميل.
